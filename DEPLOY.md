# Know Morrow News — Ubuntu Docker deployment

## Recommended server

- Ubuntu 24.04 LTS
- 2 vCPU, 2 GB RAM, 30–40 GB SSD
- 1–2 GB swap
- A public IPv4 address and at least 1 TB monthly transfer

One vCPU and 1 GB RAM can run the site at low traffic, but building the client image on that machine may run out of memory. If choosing 1 GB, create swap first or build and push the images elsewhere.

## 1. Domain and firewall

Create an `A` record for the site hostname pointing to the server. Allow inbound TCP ports `22`, `80`, and `443`, plus UDP `443`. Do not expose port `4000`.

## 2. Install Docker

Use Docker's official Ubuntu installation guide:

https://docs.docker.com/engine/install/ubuntu/

Verify the installation:

```bash
docker --version
docker compose version
```

## 3. Configure production secrets

```bash
cp .env.production.example .env.production
openssl rand -hex 32
```

Edit `.env.production`. Set the real hostname, Discord credentials, two unique random secrets, and a PostgreSQL password. A hexadecimal password generated by `openssl rand -hex 32` is recommended. Never commit this file.

In the Discord Developer Portal, add this exact OAuth2 redirect:

```text
https://YOUR_DOMAIN/api/auth/discord/callback
```

The bot must already be a member of guild `1528707402319532214` and must be able to read member roles.

## 4. Start

```bash
docker compose --env-file .env.production up -d --build
docker compose ps
docker compose logs --tail=100
```

Caddy obtains and renews the TLS certificate automatically after DNS is live and ports 80/443 are reachable.

## 5. Update

```bash
git pull
docker compose --env-file .env.production up -d --build
docker image prune -f
```

## 6. Back up persistent data

PostgreSQL and uploads live in named Docker volumes. Back up both regularly. Use `pg_dump` for the database:

```bash
mkdir -p backups
docker compose --env-file .env.production exec -T postgres pg_dump -U know_morrow -d know_morrow -Fc > backups/know-morrow.dump
docker run --rm -v know_morrow_uploads:/source:ro -v "$PWD/backups:/backup" alpine tar czf /backup/uploads.tgz -C /source .
```

Copy backups to a different machine or object-storage service. `pg_dump` provides a consistent online backup, so the API does not need to stop.

## Operations

```bash
docker compose ps
docker compose logs -f --tail=100 api
docker compose restart api
```

For this traffic level, CPU is unlikely to be the bottleneck. Watch disk usage because uploaded media is stored locally. PostgreSQL is kept private inside the Docker network and is not exposed on a public host port.
